# AGENTS.md

Millbank's checkout app: a React/Redux single-page checkout built on `@boldcommerce/checkout-frontend-library@0.66.0` (pinned, from npm). It runs in the browser and makes no server calls of its own. The Millbank storefront builds it and serves it as a static bundle.

## Repo and workflow

- GitHub: `deanwhillier/millbank-checkout` (private, detached from Bold's fork network; originally `bold-commerce/checkout-experience-templates`). Local clone: `~/Projects/millbank/checkout`. Base branch: `main`.
- One worktree per task at `~/.herdr/worktrees/checkout/<branch>`, on a feature branch. Never edit on `main`.
- Feature branch -> PR. Rebase onto `main`, don't merge `main` in. Nothing goes to `main` directly. Dean merges every PR.
- Every change gets a security review, then QA, before merge.

## Setup and commands

- Node `20.11.1` (`.nvmrc`).
- Install with `yarn install --frozen-lockfile` only. A dependency change needs a `yarn.lock` change and the reason in the PR, because the storefront builds with `--frozen-lockfile`.
- `yarn build`: production build, writes `build/one_page.js`. `yarn build-dev`: dev build. `yarn start`: watch. `yarn serve`: dev server.
- `yarn test`: jest. `yarn cover-test`: jest with an 80% global coverage threshold. `yarn lint-ci`: eslint on `src`.
- `config.json` is generated by `prebuild` from `config.example.json`. Never commit it.

## What ships and how it releases

- Only the `one_page` webpack entry ships (`src/themes/one-page/init.tsx` -> `build/one_page*`). `buy_now`, `three_page` and `app_version_check` are commented out in `webpack.config.js` and unused.
- Release: merge to `main`. The storefront team (millbank repo) then opens a PR that bumps the `checkout` submodule pointer to a commit on `main`. At deploy the storefront's `yarn build` runs `build-checkout`, which builds here and copies `build/one_page*` to `public/static/js/`.
- Checkout work never edits the storefront's `checkout/` submodule.

## Shared contracts

| Contract | Producer | Consumer | Where in checkout |
|---|---|---|---|
| Promo fields on line items: `product_data.properties.product_details` (URI-encoded JSON), `promo.{id, layerId, layerTypeName, priceOverride, rewardType (free/reduced/rebate/discount), completed}` | millbank-api (into the Bold order) | checkout | `src/components/cart-item/cartItem.tsx`, `src/components/summary-section/summarySection.tsx` (groups by `promo.id`, only `completed`), `src/components/summary-totals/summaryTotals.tsx` |
| `millbank_checkout_email` order note attribute (validated email) | checkout (`EMAIL_NOTE_ATTR_KEY` in `src/constants/constants.ts`) | millbank-api | the write, after which shipping lines are refetched |
| Hosting: routes `/:platform/:store/experience/{thank_you,order,*}`, checkout session, `window.*` globals (README table, e.g. `initializedOrder`, `publicOrderId`), `<div id="main">` | storefront | checkout | `src/themes/one-page/init.tsx` |
| Build artifact `build/one_page*`, copied to `public/static/js/` | checkout | storefront | `webpack.config.js` entry and output |

- Changing any of these needs checkout sign-off. Order: producer, then checkout, then the storefront bump.
- Don't rename the `one_page` entry or the `build/` path without coordinating; the storefront copies them by name.

## Sensitive areas (security review required)

- Payments: `src/eps`, and the payment gateway components and hooks.
- Customer data: email, addresses, order note attributes.
- Third-party scripts and keys (EPS, PayPal, Google/Apple Pay, Google Maps, Loqate, Bugsnag, analytics in `src/analytics`).

## Forbidden without Dean's approval

- Syncing or pulling upstream Bold changes.
- Production reads or external API calls.
- Editing the storefront submodule.
- Committing secrets, keys, `config.json` or customer data, in commits, PRs or test fixtures.
