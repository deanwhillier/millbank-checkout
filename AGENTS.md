# AGENTS.md

Millbank's checkout app: a React/Redux single-page checkout built on `@boldcommerce/checkout-frontend-library@0.66.0` (pinned, from npm). It has no backend of its own; it calls Bold's Checkout APIs (and EPS) from the browser. The Millbank storefront builds it and serves it as a static bundle.

## Repo and workflow

- GitHub: `deanwhillier/millbank-checkout` (public for now, so anything committed or written in a PR is world-readable; Dean may make it private again. Detached from Bold's fork network; originally `bold-commerce/checkout-experience-templates`). Local clone: `~/Projects/millbank/checkout`. Base branch: `main`.
- One worktree per task at `~/.herdr/worktrees/checkout/<branch>`, on a feature branch. Never edit on `main`.
- Feature branch -> PR. Rebase onto `main`, don't merge `main` in. Nothing goes to `main` directly. Dean merges every PR.
- Every change gets a security review, then QA, before merge.

## Setup and commands

- Node `20.11.1` (`.nvmrc`); run `nvm use` first, since plain shells may default to a newer Node.
- Install with `yarn install --frozen-lockfile` only. A dependency change needs a `yarn.lock` change and the reason in the PR, because the storefront builds with `--frozen-lockfile`. `README.md` is Bold's upstream doc and its `npm` instructions don't apply.
- `yarn build`: production build, writes `build/one_page.js`. `yarn build-dev`: dev build. `yarn start`: watch. `yarn serve`: dev server.
- `yarn test`: jest. `yarn cover-test`: jest with an 80% global coverage threshold (fails while the baseline below is red). `yarn lint-ci`: eslint on `src`.
- `config.json` is generated by `prebuild` from `config.example.json`. Never commit it.

## What ships and how it releases

- Only the `one_page` webpack entry ships (`src/themes/one-page/init.tsx` -> `build/one_page*`). `buy_now`, `three_page` and `app_version_check` are commented out in `webpack.config.js` and unused.
- Release: merge to `main`. The storefront team (millbank repo) then opens a PR that bumps the `checkout` submodule pointer to a commit on `main`. At deploy the storefront's `yarn build` runs `build-checkout`, which builds here and copies `build/one_page*` to `public/static/js/`.
- The storefront's `.gitmodules` points at `deanwhillier/millbank-checkout` (Him-Her/millbank#429); the old `checkout-experience-templates` URL redirects.
- Checkout work never edits the storefront's `checkout/` submodule.

## Shared contracts

| Contract | Producer | Consumer | Where in checkout |
|---|---|---|---|
| Promo fields on line items: `product_data.properties.product_details` (URI-encoded JSON), `price.{base, discount}`, `promo.{id, layerId, layerTypeName, priceOverride, rewardType (free/reduced/rebate/discount), completed}` | millbank-api (into the Bold order) | checkout | `src/components/cart-item/cartItem.tsx`, `src/components/summary-section/summarySection.tsx` (groups by `promo.id`, only `completed`), `src/components/summary-totals/summaryTotals.tsx` |
| `millbank_checkout_email` order note attribute (validated email) | checkout (`EMAIL_NOTE_ATTR_KEY` in `src/constants/constants.ts`) | millbank-api | `src/library/syncEmailNoteAttribute.ts`: the write, then shipping lines are refetched only when the shipping address is valid and the order requires shipping |
| Hosting: routes `/:platform/:store/experience/{thank_you,order,*}`, checkout session, `window.*` globals (README table, e.g. `initializedOrder`, `publicOrderId`), `<div id="main">` | storefront | checkout | `src/themes/one-page/init.tsx` |
| Build artifact `build/one_page*`, copied to `public/static/js/` | checkout | storefront | `webpack.config.js` entry and output |

- Changing any of these needs checkout sign-off. Order: producer, then checkout, then the storefront bump.
- Don't rename the `one_page` entry or the `build/` path without coordinating; the storefront copies them by name.

## Sensitive areas (security review required)

- Payments: `src/eps`; `src/components/{payment,eps-payment,eps-express-payment-gateway,external-payment-gateway,external-payment-gateway-iframe,display-payment-method,display-payment-methods}`; `src/hooks/useGet*Payment*`, `src/hooks/useGetExternalPaymentGateway*`, `src/hooks/useSetExternalPaymentGatewayListener.ts`; the payment and external-payment-gateway handlers in `src/library` (e.g. `externalPaymentGateway.ts`, `addPayment.ts`, `deletePayment.ts`); `src/utils/format{Stripe,Braintree,ApplePay}*`.
- Customer data: email, addresses and order note attributes, i.e. the address and email hooks, library actions, and `src/library/syncEmailNoteAttribute.ts`.
- Session tokens and auth: `jwt_token` (`src/reducer/dataReducer.ts`, `src/utils/getOrderInitialization.ts`, `window.initializedOrder`), `src/hooks/useIsUserAuthenticated.ts`.
- Error reporting and logging: `src/utils/bugReporter.ts` (Bugsnag metadata and breadcrumbs).
- HTML or script injection sinks: `dangerouslySetInnerHTML` (`src/components/life-field-html/lifeFieldHtml.tsx`), `innerHTML` (`src/components/cart-item/cartItem.tsx`, `src/utils/renderHtmlEntities.ts`), and dynamic `<script>` injection (`src/hooks/useInitiateLoqate.ts`, `src/hooks/useInitiateGoogleAutocomplete.ts`, `src/analytics/{custom,facebook,google}Analytics.ts`).
- Third-party scripts and keys: EPS, PayPal, Google/Apple Pay, Google Maps (key via `src/hooks/useGetAutocompleteAPIKey.ts`), Loqate (`src/constants/loqateConstants.ts`), Bugsnag (keys via `config.json`), analytics in `src/analytics`.
- Build config and dependencies: `webpack.config.js`, `package.json`, `yarn.lock`. This bundle runs on the payment page.
- Payment-flow changes and dependency bumps get particular scrutiny, especially bumping the pinned `@boldcommerce/checkout-frontend-library`.

## Forbidden without Dean's approval

- Syncing or pulling upstream Bold changes.
- Production reads or external API calls.
- Editing the storefront submodule.
- Adding a new third-party script, SDK, analytics or tracking destination, or sending customer data or session tokens to a new destination.
- Committing secrets, keys, `config.json` or customer data, in commits, PRs or test fixtures.
- Publishable browser-side keys already in source (e.g. Loqate) are known. Don't add new keys to source, and don't remove, rotate or move existing ones.
